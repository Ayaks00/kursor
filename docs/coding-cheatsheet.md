# Шпора по процессу кодинга — от первого лица

Коротко и по делу: как **я** писал игру, что за код где лежит и что сказать, если спросят про реализацию. Для ответов про саму идею есть `docs/qa-answers.md`.

## 1. Рассказ за минуту (можно заучить)

«Я сделал веб-платформер на чистом JavaScript без движка и сборщика. Начал с каркаса: `index.html`, CSS и точка входа `src/main.js`, где крутится `requestAnimationFrame` с фиксированным шагом 1/60 секунды. Ввод вынес в `src/input.js`: клавиши и мышь превращаются в флаги `down/pressed`, а после каждого шага `endFrame()` очищает нажатия.

Данные уровней я положил в `src/levels.js`: платформа — это отрезок с двумя парами концов (обычной и кривой) и типом `both/flat/curve`.При загрузке я один раз умножаю всё на `K = 4`, поэтому игровая логика и raster совпадают — 1920×1080.

Движок в `src/game.js` — конечный автомат состояний, физика, камера, столкновения, чекпоинты, босс. Фишка реализована парой функций: `platformEnds` интерполирует концы по коэффициенту кривизны, `platformSolid` решает, материальна ли платформа. Переключатель плавно ведёт `curvature` к цели, поэтому видно, как навесы стягиваются в идеальную точку.

Графику я рисую примитивами Canvas 2D в `src/art.js`, статичные фоны генерирую скриптом `tools/generate_backgrounds.js` и встраиваю в `src/bg-data.js` data URI — игра открывается даже с `file://`. Весь русский текст вынесен в HTML слой `src/ui.js`, на canvas текст не рисуется. Музыку синтезирую через Web Audio API в `src/audio.js`; звуки — CC0-сэмплы, встроенные как data URI. В конце сделал сборку ZIP и скрипты проверок simulates/ui-smoke/preview».

## 3. Куски кода, которые я могу показать

**Масштабирование уровней один раз:**

```js
var K = 4;
function pair(p) { return [p[0] * K, p[1] * K]; }
out.gravity = lv.gravity * K;  out.jump = lv.jump * K;
out.platforms = lv.platforms.map(p => ({ a: pair(p.a), b: pair(p.b),
  ca: pair(p.ca), cb: pair(p.cb), kind: p.kind, style: p.style }));
```

**Механика кривизны:**

```js
Game.prototype.platformEnds = function (plat) {
  var t = this.curvature;
  return [[lerp(plat.a[0], plat.ca[0], t), lerp(plat.a[1], plat.ca[1], t)],
          [lerp(plat.b[0], plat.cb[0], t), lerp(plat.b[1], plat.cb[1], t)]];
};
Game.prototype.platformSolid = function (plat) {
  return plat.kind === 'both' ||
    (plat.kind === 'flat' && this.curvature < 0.5) ||
    (plat.kind === 'curve' && this.curvature >= 0.5);
};
```

**Фиксированный шаг:**

```js
var STEP = 1 / 60;
while (acc >= STEP && guard < 6) { game.update(STEP); input.endFrame(); acc -= STEP; guard++; }
game.render();
```

**Исправленный респавн:**

```js
this.respawn = { x: cp.x - 5 * K, y: cp.y - 16 * K }; // координаты в пикселях 1920×1080
Game.prototype.respawnNow = function () {
  this.resetPlayer(); this.settleOnPlatform(); /* … */ this.setState('play');
};
```

## 4. Баги, которые я ловил, — это и есть процесс

- **Второй уровень не проходился в симуляции.** Причина: пороги скорости и гравитации остались в старых «дизайнерских» единицах, а мир уже был в пикселях. Исправил: умножил все физические константы на `K` в `scaleLevel`.
- **Страница иногда открывалась пустой из-за кэша.** Добавил `no-cache` meta, версионирование скриптов `?v`, запасной `play.html` и предупреждение, если не найден `#ui`.
- **Текст на canvas читался плохо.** Переписал интерфейс на DOM: `src/ui.js` обновляет реальные HTML-элементы, canvas оставил только для мира и эффектов.
- **После удаления экрана выхода падал smoke-тест.** Убрал состояние `exit` из теста и из логики, оставил меню только с «НОВАЯ ИГРА / КАК ИГРАТЬ».
- **Игрок проваливался при респавне на чекпоинте.** Точка сохранения считалась без `K`, то есть почти на 40 логических пикселей ниже платформы. Исправил масштаб и добавил `settleOnPlatform()`, который поднимает игрока на поверхность опорной платформы.
- **Дорожки сливались с фоном.** Добавил тёмную подложку, чёрный контур и светлый верхний край платформы.

## 5. Если спросят про код

**«Почему просто глобальный объект `KZ`?»** — Потому что нет сборщика: файлы подключаются тегами `<script>`, каждый модуль — IIFE и приклеивает свой класс к `KZ`. В консоли легко посмотреть `KZ.game` и состояние.

**«Почему не раз в кадр, а фиксированный шаг?»** — Чтобы физика не зависела от частоты монитора: на 30, 60 и 144 Гц игрок движется одинаково, а `rAF` отвечает только за отрисовку.

**«Почему платформы — данные, а не код?»** — Так я могу править уровни, не трогая движок: один массив в `levels.js` содержит все сцены, а движение и коллизии общие.

**«Как ты проверял, что игра действительно проходимая?»** — `tools/simulate.js` управляет вводом и проходит все три уровня и босса; `tools/ui-smoke.js` открывает все экраны; кадры для защиты уже включены в PDF.

**«Что было самым сложным?»** — Совместить математическую идею с удобным управлением: платформа должна существовать только в одном режиме, но переключение происходит в прыжке. Пришлось вынести интерполяцию концов и проверку материальности в отдельные функции и сгладить переход.
